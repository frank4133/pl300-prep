① 準備資料（Prepare the data,25–30%）

取得資料與連線模式

  • Import（匯入）：資料快取到模型內，查詢最快、功能最完整；需排程重新整理。預設且最常考的「效能最佳」答案。
  • DirectQuery：不快取，查詢即時送到來源；適合近即時資料或超大資料量，但視覺效果較慢、DAX/PQ 功能受限。
  • Dual（雙重）：同時可作為快取或直查，常用於「維度表」搭配 DirectQuery 事實表 + Import 彙總表（複合模型），可減少限制關聯性並提升效能。
  • Live Connection（即時連線）：連到 Analysis Services 或已發佈的 Power BI 語意模型；重用既有模型與量值時「開發工作量最小」的選擇是 Power BI semantic model（資料集）連接器。
更新需求建議儲存模式
近即時（near real time）DirectQuery
每日/每週定期更新、追求視覺效能Import（或彙總表 Import）
維度表連接 DirectQuery 事實表Dual

Power Query 常考轉換

  • Merge（合併）= 橫向 JOIN（依索引鍵加欄位）；Append（附加）= 縱向 UNION（加資料列）。「每位客戶一列並帶出城市」→ Merge；「兩個相同結構的表合成一張」→ Append Queries as New，並停用原始查詢的載入以縮小模型。
  • Group By（分組依據）：彙總計算（加總、計數、最大最小）。
  • Pivot / Unpivot:Unpivot 把「多個屬性欄」轉成 屬性/值 兩欄（寬轉長）；Pivot 相反（長轉寬）。欄名是年份、月份等資料值時，幾乎都選 Unpivot。
  • Transpose（轉置）：整表列欄互換，與 Pivot/Unpivot 不同。
  • Use first row as headers、Fill Down/Up（向下/向上填滿）：處理合併儲存格造成的 null。
  • Split Column（分割欄）、Column From Examples（依範例新增欄）：依樣本自動產生轉換。
  • 資料類型錯誤 Expression.Error: cannot convert：通常是欄位含非數字字元或來源欄位改名（column wasn't found → 來源欄位被重新命名）。

資料剖析（Data Profiling）

  • Column quality（資料行品質）:Valid / Error / Empty 百分比。
  • Column distribution（資料行分佈）:Distinct（相異）與 Unique（唯一）個數——判斷可否當主索引鍵。
  • Column profile（資料行設定檔）：統計值（最小、最大、平均）與值分佈。預設僅剖析前 1,000 列，可改成整個資料集。

查詢摺疊與效能

  • Query Folding（查詢摺疊）：步驟轉譯回來源的原生查詢（SQL）。以「View Native Query」檢查；若灰色代表無法摺疊。增量重新整理（Incremental refresh）需要來源支援查詢摺疊。
  • 參考（Reference） vs 複製（Duplicate）：Reference 引用原查詢結果，原查詢改動會影響下游。
  • 減少模型大小：移除不必要的欄/列、關閉自動日期/時間、避免高基數欄位（如 GUID）、彙總。

② 模型化資料（Model the data,25–30%）

星型結構與關聯性

  • 事實表（Fact）存交易/量值，維度表（Dimension）存描述屬性；維度表以一對多（1:*）連向事實表，交叉篩選方向預設為「單向」（維度 → 事實）。
  • 基數：一對多最常見；多對多盡量避免，可用橋接表（bridge table）化解。
  • 雙向交叉篩選（Both）會增加模稜兩可與效能風險，僅在必要（如橋接表）時使用；需要讓 RLS 隨雙向關聯傳遞時，勾選「Apply security filter in both directions」。
  • 非作用中關聯（虛線）以 USERELATIONSHIP() 在量值中啟用，常用於一張事實表有訂單日期/出貨日期兩個日期欄（role-playing dimension）。
  • 日期表：標示為日期資料表（Mark as date table）才能在自訂日期表上使用時間智慧函數；需為「每日一列、連續不中斷」的日期欄。

計算資料行 vs 量值 vs 計算資料表

計算資料行（Calculated column）量值（Measure）
計算時機資料重新整理時，逐列計算並儲存查詢時依篩選內容動態計算
內容列內容（row context）篩選內容（filter context）
模型大小佔用記憶體不佔用（只存公式）
適用當作交叉分析篩選器/座標軸、分組彙總數字、KPI（優先選擇，考題常考「最小化模型大小」→ 量值）

核心 DAX 觀念

  • CALCULATE(運算式, 篩選…)：改寫篩選內容的核心函數；搭配 FILTER、ALL、ALLSELECTED、KEEPFILTERS、REMOVEFILTERS。
  • 迭代函數 X 系列:SUMX / AVERAGEX / COUNTX / MAXX 逐列運算再彙總，如 SUMX(Sales, Sales[Qty]*Sales[Price])。
  • 時間智慧:TOTALYTD / DATESYTD（年初至今）、SAMEPERIODLASTYEAR / DATEADD(dates,-1,YEAR)（去年同期）、DATESINPERIOD（滾動區間，如近 12 個月）、PREVIOUSMONTH。
  • 計數:COUNT（數值列）、COUNTA（非空白）、COUNTROWS（資料列數）、DISTINCTCOUNT（相異值）。
  • 關聯取值:RELATED（多端取一端）、RELATEDTABLE（一端取多端）、LOOKUPVALUE（無關聯查值）。
  • 其他常考:DIVIDE(a,b,alt) 安全除法、SELECTEDVALUE、HASONEVALUE、ISFILTERED、CALCULATETABLE、SUMMARIZE、ADDCOLUMNS、CROSSFILTER、TREATAS。
  • 變數 VAR … RETURN 提升可讀性與效能（同一運算式重複使用時只算一次）。
Sales YTD = TOTALYTD ( [Sales Amount], 'Date'[Date] )
Sales LY  = CALCULATE ( [Sales Amount], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )
Rolling12 = CALCULATE ( [Sales Amount],
              DATESINPERIOD ( 'Date'[Date], MAX ( 'Date'[Date] ), -12, MONTH ) )

資料列層級安全性（RLS）

  • Desktop：「模型化 → 管理角色」以 DAX 資料表篩選定義角色，如 [Region] = "West" 或動態 [Email] = USERPRINCIPALNAME()。
  • Desktop 以「檢視身分（View as）」測試；服務中於語意模型的 [安全性] 頁面指派使用者/群組到角色。
  • RLS 只對 Viewer（檢視者）角色生效；工作區 Admin / Member / Contributor 不受 RLS 限制。

效能最佳化

  • Performance Analyzer(Desktop)：錄製並檢視每個視覺效果的 DAX 查詢耗時，匯出 JSON。
  • Best Practice / VertiPaq 分析、DAX Studio：找出高記憶體欄位。
  • 降低基數（移除時間的秒數、拆分 datetime）、改用整數索引鍵、量值取代計算資料行、彙總表（Aggregations）。
  • 大型語意模型儲存格式（Large dataset storage format）:Premium 上超過預設大小限制時啟用。

③ 視覺化與分析資料（Visualize and analyze the data,25–30%）

需求視覺效果
單一重點數字（總數、KPI）卡片（Card） / KPI
目標達成進度量測計（Gauge）、KPI
時間趨勢折線圖；含預測 → 折線圖分析窗格的 Forecast
類別比較橫條圖/直條圖
兩數值關係 + 分佈散佈圖（Scatter），可加播放軸

矩陣式明細與小計矩陣（Matrix），支援階層下鑽與屬性（+/-）展開

互動、篩選與導覽

  • 篩選層級：視覺效果 → 頁面 → 所有頁面（報表）；交叉分析篩選器（Slicer）可透過「同步交叉分析篩選器」跨頁同步。
  • 編輯互動（Edit interactions）：控制某視覺效果對其他視覺效果是篩選、醒目提示或無作用。
  • 鑽研（Drill through）：從摘要頁右鍵帶篩選跳到明細頁；目標頁設定鑽研欄位，可加「返回」按鈕。
  • 書籤（Bookmark）+ 按鈕 + 選取窗格：製作導覽、重設篩選、切換視覺效果顯示。
  • 工具提示頁（Tooltip page）：自訂頁面作為滑鼠停留提示。
  • 條件式格式設定：依量值變更背景/字型色、資料橫條、圖示；「依欄位值」可用色碼欄位。
  • Top N 篩選：視覺效果層級篩選依量值取前 N 名。
  • 群組與量化（Groups / Bins）：把連續值分箱或把類別歸組。
  • 分析窗格：平均/中位數/百分位數線、趨勢線、誤差線；折線圖預測（Forecast）與異常偵測（Anomaly detection）。
  • 行動版配置（Mobile layout）：直向手機檢視另行排版。

儀表板（Dashboard）vs 報表（Report）

  • 儀表板僅存在於服務，由多個報表「釘選」磚組成；可設定資料警示（Alert）——僅支援卡片、KPI、量測計。
  • 警示觸發後可透過 Power Automate 寄信給其他人或執行流程（內建警示只通知本人）。
  • 即時磚快取更新時間顯示於磚；報表主題與儀表板主題分開設定。
  • 訂閱（Subscribe）定期寄送報表/儀表板快照；註解（Comments）可 @ 提及使用者（含外部使用者）。

④ 管理與保護 Power BI(Manage and secure,15–20%)

工作區角色（常考！）

角色關鍵權限
Admin全部權限 + 刪除工作區、管理所有成員（含其他 Admin）、更新/刪除 App
Member發佈/取消發佈與更新 App、新增較低權限成員、共用內容（「能邀請他人 + 最小權限」→ Member）
Contributor建立/編輯/刪除工作區內容、排程重新整理；不能共用或發佈 App（除非 Admin 委派「更新 App」設定）
Viewer僅檢視與互動；唯一會套用 RLS 的角色
  • 通知工作區問題：把群組加入工作區連絡人清單（Contact list），不需給角色（最小權限）。
  • App：對大量檢視者散發內容的建議方式；可設定對象（Audience）、允許使用者以 Build 權限連基礎語意模型、可安裝於 Teams。

共用與權限

  • 語意模型權限：Read（檢視）、Build（用資料自建報表/連線分析，Analyze in Excel 需要）、Reshare、Write。
  • 「用既有語意模型自建報表」→ 給 Build 權限即可，不必給工作區角色。
  • 背書（Endorsement）:Promoted（推薦，擁有者即可）與 Certified（認證，需租用戶管理員授權的認證者）——「財務決策資料需審核核可」→ Certified。
  • 敏感度標籤（Sensitivity labels）:Microsoft Purview 資訊保護；可加密匯出檔（PDF/Excel/PPT）、防止 PII 匯出；需要 Azure Information Protection 授權。
  • 資料譜系（Lineage view）：檢視從來源→語意模型→報表→儀表板的相依關係與上游影響。

重新整理與閘道

  • 來源在地端（檔案伺服器、SQL Server、內網）→ 需要 On-premises data gateway（標準模式可多人共用多來源；Personal mode 僅個人）。
  • 雲端來源（OneDrive、SharePoint Online、Azure SQL）不需閘道；OneDrive/SharePoint 上的檔案約每小時自動同步。
  • 排程重新整理：共用容量每日最多 8 次，Premium 48 次；連續 2 個月無人使用會因閒置而停用排程，任何人開啟相關儀表板/報表即恢復。
  • 增量重新整理（Incremental refresh）：以 RangeStart/RangeEnd 參數過濾，僅重新整理最新分割區；需查詢摺疊支援。
  • 重新整理失敗通知：語意模型設定中可寄給擁有者與指定連絡人。

部署與治理

  • 部署管線（Deployment pipelines）：開發 → 測試 → 生產三階段，支援階段間比較與部署規則（不同階段換資料來源/參數）；需 Premium/PPU/Fabric 容量。
  • 範本檔 .pbit：保留模型/查詢/報表定義但不含資料，可帶參數提示——「發給同事重複使用又不外洩資料」→ .pbit。
  • .pbip / Power BI Desktop 開發者模式：專案格式利於版本控制。
  • 使用量計量報告（Usage metrics）：報表/儀表板檢視次數與使用者。
  • Analyze in Excel：以樞紐分析表連線語意模型；在 Excel 中取得資料 → Power BI 語意模型。

DAX 速查表

目的寫法
總銷售額Total Sales = SUM ( Sales[Amount] )
逐列相乘再加總Revenue = SUMX ( Sales, Sales[Qty] * Sales[Price] )
去年同期CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )
年初至今TOTALYTD ( [Total Sales], 'Date'[Date] )
占整體比例DIVIDE ( [Total Sales], CALCULATE ( [Total Sales], ALL ( Product ) ) )
已選項目占比（受其他篩選影響）DIVIDE ( [Total Sales], CALCULATE ( [Total Sales], ALLSELECTED () ) )
不重複客戶數DISTINCTCOUNT ( Sales[CustomerID] )
非作用中關聯CALCULATE ( [x], USERELATIONSHIP ( Sales[ShipDate], 'Date'[Date] ) )

常見陷阱：SUM 只能吃單一欄位；需要列運算時用 SUMX。COUNT 不數文字空白，數列數請用 COUNTROWS。時間智慧需要「標示為日期資料表」的連續日期表。
